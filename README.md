# AMLET — 2026 rebuild

[![build](https://github.com/fbastin/amlet-legacy/actions/workflows/build.yml/badge.svg)](https://github.com/fbastin/amlet-legacy/actions/workflows/build.yml)

AMLET (*Another Mixed Logit Estimation Tool*) estimates multinomial and
mixed logit models by maximum simulated likelihood. It includes the adaptive
Monte Carlo trust-region algorithms (BTR / BTRDA) developed by
F. Bastin, C. Cirillo and Ph. L. Toint. The code is no longer actively
developed. This directory makes the last release, **AMLET 0.13.1**, build and
run on current Linux systems, with as few source changes as possible. It was
tested with GCC 13.3 on Ubuntu 24.04 in October 2026, and the CI builds it
with GCC 13 (Ubuntu 24.04) and GCC 15 (Ubuntu 26.04). The bugs found on the
way are fixed (see below). One of them is in the random number generator: by
default, simulated results differ from AMLET 0.13.1, and `legacy_rng = true;`
in the driver file reproduces them.

The directory contains:

| Path | Content |
|---|---|
| `src/oratio-0.7.5/` | ORATIO numerical libraries (random numbers, QMC, statistics, linear algebra). The Fortran integer type in `f2c.h` is fixed, and `config.guess` replaced (see below). |
| `src/ophelia-0.7.4/` | OPHELIA nonlinear optimisation library (trust-region solvers). One missing prototype added, and `config.guess` (see below). |
| `src/amlet-0.13.1/` | AMLET, with the fixes listed below. |
| `patches/` | All code changes to the original `amlet-0.13.1.tar.gz`, `ophelia-0.7.4.tar.gz` and `oratio-0.7.5.tar.gz` (the license change is not included). |
| `build.sh` | Builds the three packages into a local prefix. Needs no root access. |
| `run_examples.sh` | Runs the examples and checks the results against reference values. |
| `run_checks.py` | Checks that errors in driver and data files are reported, and some options (26 checks, a few seconds). |
| `examples/` | Redistributable examples (see below). |
| `doc/` | User manuals (AMLET, OPHELIA, ORATIO), rebuilt in 2026 from the LaTeX sources in `src/*/doc`. The previous PDFs dated from 2011 and described AMLET 0.10.6. |

## Quick start

```sh
# Debian/Ubuntu prerequisites (or libopenblas-dev instead of libblas-dev + liblapack-dev)
sudo apt install build-essential libblas-dev liblapack-dev python3 curl git

git clone https://github.com/fbastin/amlet-legacy.git
cd amlet-legacy
bash build.sh                 # installs into ./local  (about 1 minute)
bash run_examples.sh          # 19 examples, about 1.5 minutes
python3 run_checks.py         # errors in driver and data files
./local/bin/amlet my_driver   # estimate your own model
```

If the source tree sits on a filesystem mounted `noexec` (for example an
external backup disk), build and run somewhere else:

```sh
PREFIX=$HOME/amlet BUILD=/tmp/amlet-build bash build.sh
AMLET=$HOME/amlet/bin/amlet RUN=/tmp/amlet-run bash run_examples.sh
```

Bison/flex, autotools and LaTeX are **not** needed: the generated parser,
scanner and `configure` scripts are already in the source trees. `build.sh`
detects BLAS/LAPACK automatically. To choose them yourself, set
`BLAS_LIBS="-lopenblas"`.

A model is described by a *driver file*: model size, distribution of each
coefficient, data file, algorithm, number of draws, and so on. See
`doc/amlet_manual.pdf` and the drivers in `examples/`. AMLET reads data in
the "Train96" (cross-section) and "Train99" (panel) formats described in the
manual.

## Examples and validation

| Example | Data | Check |
|---|---|---|
| `australia/driver_mnl` | Hensher & Greene intercity mode choice (210 obs., shipped with AMLET; also available as `TravelMode` in the R package AER) | LL = −199.1284. Coefficients are identical to the conditional logit in Greene, *Econometric Analysis*. |
| `australia/driver_mmnl` | same | Mixed logit with one normal coefficient, 1000 draws: LL = −178.996 |
| `australia/driver_mmnl_legacy` | same | Same model with `legacy_rng = true`: LL = −178.491, as AMLET 0.13.1 |
| `australia/driver_mnl_bfgs`, `driver_mnl_rtr` | same | Other optimization methods (BFGS line search, retrospective trust region): same optimum as `driver_mnl` |
| `australia/driver_mmnl_halton`, `_sobol`, `_lattice`, `_mlhs` | same | Quasi-Monte Carlo draws: LL = −178.625, −178.663, −178.655, −178.656 |
| `australia/driver_mmnl_uniform`, `_spline`, `_ecuyer` | same | Uniform coefficient with the classical covariance; nonparametric (B-spline) coefficient with monotonicity constraints; L'Ecuyer 1988 generator |
| `simulated/driver_errc` | Synthetic data generated by AMLET | Error-components model. The true parameters (all equal to 1) are recovered. |
| `simulated/driver_errc_import` | the data written by `driver_errc` (Train99) | Same results as `driver_errc` |
| `simulated/driver_errc_legacy` | same, generated with `legacy_rng = true` | LL = −4789.683, as AMLET 0.13.1 |
| `simulated/driver_panel` | Synthetic panel generated by AMLET | Five random coefficients. The true values (mean 0.5, std 1) are recovered. |
| `simulated/driver_panel_halton` | same | Scrambled Halton draws |
| `swissmetro/driver_mnl` | Swissmetro SP data, downloaded from Biogeme by `run_examples.sh` (not shipped) | LL = −5331.252. Coefficients and robust standard errors are identical to Biogeme's example `01logit`. |
| `swissmetro/driver_mmnl` | same | Normal mixture on the time coefficient, 1000 draws: LL = −5215.963 |

`run_examples.sh` compares the log-likelihood and the standard error of the
first parameter with `examples/reference_values.tsv`. `run_checks.py` changes
the drivers or the data of the examples, and checks that AMLET reports each
error (see "Values in the driver file" below) with a message and a non-zero
exit code, and that `draws = old;` reproduces an estimation.

The simulated log-likelihood and the robust standard errors of
`australia/driver_mmnl` were recomputed independently, in Python (numpy and
scipy), from the data and the draws that AMLET saves (`drawsname`): the
log-likelihood is identical to all printed digits, and the standard errors
(sandwich H⁻¹BH⁻¹ with the exact Hessian, `hessian_approx = false`) to 5
digits; with `robust = false`, AMLET gives H⁻¹. The same holds for the panel
model of `simulated/driver_panel` (five random coefficients, one of them
lognormal), with 200 draws. On the Australia model, `mcbfgsda` reaches
another local maximum of the same simulated likelihood (LL = −177.978,
against −178.996 for `mcbtrda`): the sign of the standard deviation is not
identified, and with a finite number of draws the two signs give two
maxima.

Simulated results depend on the pseudo-random draws. They are reproducible
for a given `seed1` on a given build. A different BLAS or compiler may change
the last digits, which is why the mixed-logit tolerances in
`examples/reference_values.tsv` are looser. The standard errors of
`australia/driver_mmnl` come from the BFGS approximation of the Hessian
(`hessian_approx = true`), which depends on the optimisation path: they vary
by about 3% between builds, and are checked to within 10%.

The rebuilt executable was also checked against output files written by
historical AMLET versions on the original (non-redistributable) research
data sets. Two deterministic multinomial logit models reproduce the archived
results to all printed digits:
- a parking-choice SP data set, LL = −882.6456797 (AMLET 0.8.2, 2004);
- a cybercar mode-choice data set, LL = −2932.920769 (AMLET 0.10.5).

Mixed logit estimates from older versions are reproduced only up to
simulation error, not digit for digit. The draw generation and the adaptive
sampling strategy evolved between versions. For example, on the Mobidrive
panel with 1000 draws and the same seed, this build gives LL = −6445.78
with `legacy_rng = true`, while AMLET 0.8.3 (2004) gave −6448.13; the coefficients agree to about two
significant digits. To reproduce published mixed logit results exactly, you
would need the AMLET version that was used at the time (the archive keeps
releases 0.7 to 0.13).

## Changes with respect to the original tarballs

The 2015 AMLET tarball did not compile with any compiler. With the fixes
below, compilation needs no special flags.

1. **Missing file**: `src/exec.h` was missing from the tarball. It is restored from 0.12.0; it only declares a prototype.
2. **Undefined `_max` / `_min`**: they now use ORATIO's `nt_max` / `nt_min` macros, as AMLET 0.12.0 did.
3. **Global variables defined in headers** (`amlet_config.h`, `log.h`): these break linking with GCC ≥ 10 (`-fno-common`). They are now declared `extern` and defined once in `amlet/model.c`.
4. **`inline` functions in `.c` files**: under C99 semantics (GCC ≥ 5) they emit no external symbol, so linking failed. The `inline` qualifier was removed; the behaviour is unchanged.
5. **Missing prototypes**: `simulation_bias()`, `isnan()`, `cblas_dcopy()`, and `yylex()` in the driver parser. GCC ≥ 14 rejects calls to undeclared functions.
   - `simulation_bias()` returns a `double` but was implicitly declared as `int`. **In builds of the 0.13.x tarballs, the bias correction (`bias = 1`) therefore used a garbage value.** This is fixed. Earlier versions (≤ 0.12) are not affected.
6. **Log-likelihood totals for panel data** (`np < nobs`): the "Total" column, ρ² and the likelihood-ratio statistic multiplied per-observation averages by the number of individuals. They now use the correct count, consistent with AMLET 0.10.x. Parameter estimates were never affected.
7. **Out-of-bounds accesses**, found with AddressSanitizer: two file-name buffers in `amlet/io.c` were one byte too short, and at the last draw `sll_derivate_utilities()` (`amlet/likelihood.c`) read one element past the array of draws for a constant coefficient. The value read was not used, so the results do not change.
8. **Long messages**: `print_msg()` and `amlet_print_msg()` (`amlet/io.c`) expected `vsnprintf()` to return −1 when the buffer was too short, as before C99; messages longer than 1023 characters were silently truncated.
9. **Cosmetics**: a leftover debug message ("Coucou 1") is removed, and `--help` no longer lists the options `-s`, `-l` and `-f`, which 0.13 no longer accepts.

**Standard errors (ORATIO `f2c.h`).** The C code declared Fortran integers
as `long` (8 bytes), while gfortran's `INTEGER` has 4. In
`op_matrix_sy_inverse()` (OPHELIA), the Cholesky factorisation `dpotrf_`
then set only half of `info`; the other half was whatever was on the stack.
When it was not zero, a successful factorisation was treated as a failure,
and the fallback code, which expects both halves of the Hessian to be filled,
inverted only its diagonal. The standard errors were then wrong, by a factor
of up to 5 in the mixed logit examples, while the estimates and the
log-likelihood were right. With GCC 13 and its default options the stack
happened to be clean, so the results above are not affected; with GCC 15 on
Ubuntu 26.04, or with `-march=x86-64-v3`, the four mixed logit examples were.
`integer` and `logical` are now `int`. Older 64-bit builds may also have been
affected, depending on the compiler and its options.

**Random numbers (ORATIO MRG32k3a).** The default generator of AMLET was
not L'Ecuyer's MRG32k3a. In `ran/mrg32k3a.c`, its first component used
x(n−1) instead of x(n−2). In `ntools/modular.c`, `nt_modular_vecvec()` added
the running sum again at each step (`y += ...` instead of `y = ...`), so the
jumps to the next stream or substream were not reduced modulo m. Both are
fixed, and the draws are now those of L'Ecuyer's MRG32k3a: 10^6 draws after
two substream jumps, as AMLET makes them, are identical to those of
RandomDataStreams.jl, and the first draws of a stream, of its substreams and
of the next stream are identical to R's `L'Ecuyer-CMRG`
(`parallel::nextRNGSubStream`, `nextRNGStream`). The results that depend on
random draws (mixed logit, synthetic data) therefore differ from AMLET
0.13.1. To reproduce them, add

```
legacy_rng = true;
```

to the driver file: the six examples then give the same output as
AMLET 0.13.1, to all printed digits, and the results file says "Random
draws: legacy MRG32k3a streams". The driver also accepts
`rangen = mrg32k3a;`, which was missing.

Also in ORATIO, two functions that AMLET does not use called themselves
forever, `ran_johnsonSB_set_parameters()` and `ran_mgbm_generate_pathx()`,
and `ran_geometricbrownian_generate_pathx()` ignored `incx` when taking the
exponential of the path. They are fixed.

**Driver options that did not work.** Running every option of the driver
file under AddressSanitizer and UndefinedBehaviorSanitizer found the
following; the examples above now test most of them.

- **`niter`** was ignored by the methods with a variable sample size (`mcbtrda`, `mcrtrda`, `amlet/amlet_btr.c`): when the sample size stalled, AMLET iterated forever.
- **Quasi-Monte Carlo draws and variable sample size.** `mcbtrda` and `mcrtrda` estimate the simulation error as for independent draws. With Halton, Sobol, lattice or MLHS draws they stalled, or stopped with 32 draws. AMLET now uses `mcbtr` or `mcrtr` instead, with a warning.
- **Sampling methods.** `mlhs` gave Monte Carlo draws; it now uses ORATIO's modified Latin hypercube sampling. `faure`, which is not implemented, also gave Monte Carlo draws; it is now an error. With `lattice`, the generating vector of the largest tabulated lattice not greater than `nrep` was used with `nrep` points; `nrep` is now set to the number of points of that lattice (887 for 1000).
- **`randomization`** was ignored. All individuals use the same Halton points, each with its own random shift; `scrambling` now adds the Braaten-Weller permutations, and `shuffling` shuffles the order of the points of each individual. With `legacy_rng = true`, it is still ignored.
- **`robust = false`** printed the robust covariance matrix, labelled "Standard estimation". It now prints the inverse of the Hessian.
- **`validation = true`** was always disabled: the driver checks ran before AMLET knew the number of random coefficients, so every model was checked as a multinomial logit, and the checks for mixed logit models (`nrep` ≥ 10, data format) never ran.
- **Method names**: the results printed `mcrtrda` for `mcbtrda`, and vice versa.
- **Truncated normal and Bernouilli coefficients** in `btype` were estimated wrongly: `truncated_normal_b` had no derivative for its spread, and its draws were uniform; `truncated_normal` had no derivatives. They are now an error in `btype`, and remain available in `bgentype` to generate synthetic data.
- **Crashes**: `nnests` other than 1 (nested logit models are not supported), and `mcbtrc` without spline coefficients, wrote past their arrays. The first is now an error; the second uses `mcbtr`.
- **Errors in the driver or the data.** A `btype`, `bgentype` or `bgen` of the wrong length was reported, but AMLET went on, past its arrays; a `b` of the wrong length ended with "normal termination" and exit code 0. In the Train96 format, without `iddep` AMLET read the choice row as a variable, past its arrays, and a truncated data file gave undefined values. AMLET now stops with a message and a non-zero exit code.
- **ORATIO**: the padding of the random shifts of quasi-Monte Carlo points, `1.0/(4.0*(1 << 31))`, overflowed and was subtracted instead of added (`legacy_rng = true` keeps it). The `ecuyer` generator (L'Ecuyer 1988 with a shuffle table) used unsigned integers and an uninitialised shuffle table, and crashed; it now gives the draws of Numerical Recipes' `ran2` (10^5 draws checked). Scrambled Halton sequences beyond dimension 16 read past the permutation table.

**Values in the driver file, and checks of the data.** The parser and the
data readers did not check what they read:

- **Type of the values.** A value was stored as read, in a union, whatever the type of the parameter: `niter = 100.0;` gave 0 iterations, `nrep = 1e3;` was read as 0, and `eps = 1;` left `eps` almost unchanged. A real with an integer value is now accepted for an integer parameter, and an integer for a real one; any other mismatch is an error. A list given to a single-valued parameter (`niter = {100};`), or `b[1] = ...`, wrote past the parameter or crashed; these are errors too.
- **Unknown names** (`nitre = 100;`) were ignored silently; AMLET now prints a warning. `nests = 1;`, the name of `nnests` in AMLET ≤ 0.10, crashed the parser; it is now read as `nnests`, with a warning. `input "file";` opened the file and did nothing; it is now ignored with a warning.
- **Synthetic data.** `alttypes[i]` and `altvalues[i]` shorter than the model needs were read past their end, and silently gave other data; `generate` before `nalt` tried to allocate 2^64 bytes, and `nalt` changed after `generate` crashed. These are now errors.
- **Dimensions.** Without `nalt`, AMLET stopped with "not enough memory"; with `nalt = 1`, it printed a log-likelihood of 0; `nobs = 0` divided by zero; with `censor = 1` and no valid `idcensor`, the availabilities were undefined. A negative `seed1` seeded MRG32k3a with 2^64 − |seed1|, which is not a valid state. These are now errors.
- **Choices.** In the Train96 format, a choice row without a 1 left the choice undefined (the Australia data with one such record gave LL = −200.42 instead of −199.13, without any message), and a row with several 1 kept the last one. In Train99, a choice outside 1 to `nalt` was read past the arrays. AMLET now stops with the number of the record.
- **Precision of the files.** Synthetic data were exported with 6 significant digits (`%g`), so that estimating from the exported files gave other results; they are now written with 17 (`%.17g`), and `simulated/driver_errc_import` gives the results of `driver_errc`. The draws saved with `drawsname` had 16 digits: `draws = old;` read them back with another rounding, and the Australia mixed logit ended after 66 iterations instead of 70, with LL = −178.9961262 instead of −178.9961242. ORATIO now writes 17 digits, and the estimation is reproduced exactly.
- **Bias of simulation.** When the accuracy was not estimated (methods with a fixed sample size, without `statistics`), the results printed "Bias of simulation" with whatever value was on the stack, if it was negative: e.g., −5.3e+303 with GCC's `-ftrivial-auto-var-init=pattern`.
- `mcrtrda` writes the sample size of each iteration to `sizes.txt`, in the current directory; it crashed when the file could not be created.

**Fixed coefficients, bias correction, and options that did nothing.**

- **Fixed coefficients** (`FIXED` in `btype`). In a multinomial logit, the gradient was written past its arrays, and AMLET crashed; fixed coefficients are now supported (log-likelihood, estimates and robust standard errors checked against an independent computation). In a mixed logit, the t-statistic of the j-th estimated parameter divided the j-th value of the vector of all parameters, fixed ones included: every t-statistic after a fixed coefficient was wrong (276.4 instead of 3.54 on the Australia model). Without `b`, the fixed values were undefined; this is now an error.
- **Correction of the simulation bias** (`bias = 1`, the default). The optimization uses the simulated log-likelihood corrected for the simulation bias, and the results gave the corrected value without saying so. They now say it, and give the simulated log-likelihood without the correction (−5796.274 for `simulated/driver_panel`, whose results give −5791.972). The correction estimates the error of the simulated probabilities as for independent draws: with quasi-Monte Carlo draws it is now turned off, with a warning. `simulated/driver_panel_halton` (200 Halton points) therefore changes: LL = −5802.493, and the standard error of the first parameter is 0.0252 instead of 0.0388 (0.0253 for `driver_panel`, with 1000 Monte Carlo draws).
- **Options that did nothing.** `level_accuracy`, documented in the manual and used by the methods with a variable sample size, was not known to the parser: it was ignored. It is now read. `rescale`, `rescalidx`, `rescalval`, `ignore`, `synthetic` and `varrep` are read, but not implemented in AMLET 0.13.1; they now give a warning.
- **Results file.** A list of the estimates, without a title and left from debugging, preceded the table of estimates; the header "Standard deviation" ran into the next one. The t-statistics are absolute values, and the header now says `|t-statistic|`.
- **`alternatives_sampling`** (experimental and not documented: it writes the data with sampled alternatives to `intermediaire`, then stops) swapped the arguments of the integer generator, which read past a variable on the stack and drew integers in [0, 1); with 3 alternatives or more it crashed or looped forever, and it freed memory twice. It now draws from `seed1`.
- `draws = old;` with `qmcrep` > 1 read only the draws of the first replication; a warning of `validation = true` lacked its argument.

In OPHELIA 0.7.4, `ophelia/btr.h` now declares `nlp_set_derivatives_type()`,
which `rtr.c` calls; without it, GCC ≥ 14 stops with an error. In the active
sets of the monotonicity constraints (`mcbtrc`, `ophelia/activesets.c`), a
misplaced parenthesis, `fabs(p <= DBL_EPSILON)`, accepted any negative
direction as zero; the spline example gives the same results. The code
changes are in `patches/amlet-0.13.1-2026.patch`,
`patches/ophelia-0.7.4-2026.patch` and `patches/oratio-0.7.5-2026.patch`.

ORATIO 0.7.5 and OPHELIA 0.7.4 shipped a `config.guess` from about 2000. Its
test program calls `printf()` without `<stdio.h>`, so with GCC ≥ 14
`configure` stops with "cannot guess build type". It is replaced by the
`config.guess` of AMLET 0.13.1 (2009-11-20), which matches their
`config.sub` (2009-06-11). The patches do not include this file. Their
`install-sh`, `mkinstalldirs`, `test-driver`, `config.guess` and `config.sub`
are also made executable, as in AMLET: on Ubuntu 26.04, whose `mkdir` comes
from uutils coreutils, `make install` runs `install-sh`.

## Known limitations (not changed)

- The log-likelihood "at constants" is not computed in 0.13.1 (printed as 0).
- `seed2` is not implemented (see `src/amlet-0.13.1/TODO`).
- With `legacy_rng = true`, the generator is not MRG32k3a: its statistical properties are unknown, so use it only to reproduce earlier results. Its states are not reduced modulo m, and some products exceed 2^53: the draws then depend on floating-point rounding, and fused multiply-add instructions (FMA, as on Ubuntu 26.04 or with `-march=x86-64-v3`) change them completely. `build.sh` therefore always compiles with `-ffp-contract=off`, which gives the same legacy draws everywhere.
- In `set_beta()` (`amlet/likelihood.c`), the antithetic transformation is also applied to the (unused) draw of constant coefficients. The code is misleadingly indented, but the result is harmless. `sll_derivate_utilities_mvn()` is never called and uses an uninitialised variable.
- `method = none` is not supported: AMLET stops with "unsupported method". The bootstrap code cannot be reached (`nsim` is always 1).
- `rescale`, `rescalidx`, `rescalval`, `ignore`, `synthetic` and `varrep` are not implemented (AMLET warns), and `alternatives_sampling` is experimental.
- Only the `amlet` and `src` subdirectories of AMLET are built. The original `test/` program and the LaTeX manual sources are kept but not built.
